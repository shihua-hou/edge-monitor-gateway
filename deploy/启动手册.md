# 从零启动一遍（实测流程）

三台角色：

| 角色 | 地址 | 跑什么 |
|------|------|--------|
| 本机 Windows | — | 传文件、Keil 烧录 |
| VM (Ubuntu) | `192.168.100.6` | MQTT broker、Web 大屏、交叉编译 |
| 板子 (i.MX6ULL) | `192.168.100.3` | CAN 网关、Qt 界面、摄像头 |

数据流：`STM32 ──CAN──► 板子 ──MQTT──► VM(broker) ──► Web 大屏`

---

## 开 4 个终端

| 终端 | 用途 | 打开方式 |
|------|------|---------|
| **T1** | 本机 PowerShell，传文件 | Win+X → 终端 |
| **T2** | VM，跑 broker / Web | `ssh user@192.168.100.6` |
| **T3** | 板子，跑网关 / UI | `ssh -oHostKeyAlgorithms=+ssh-rsa root@192.168.100.3` |
| **T4** | VM 第二个窗口，实时看数据 | `ssh user@192.168.100.6` |

> 板子那条必须加 `-oHostKeyAlgorithms=+ssh-rsa`：板子的 SSH 服务老，
> 新版 OpenSSH 默认禁用了 ssh-rsa 主机密钥算法，不加会报
> `no matching host key type found`。

---

## 阶段 0：确认板子网络（T3）

板子 SSH 连不上就得先用串口进去救。WiFi 断过的话：

```sh
iwconfig wlan0 | head -2
```

显示 `ESSID:"Fly-7922"` 就是连着的。如果 `unassociated`，恢复：

```sh
wpa_supplicant -B -i wlan0 -c /etc/wpa_supplicant.conf -D wext
udhcpc -i wlan0
```

> **`-D wext` 不能省**。RTL8188EU 是 Realtek 老驱动，不支持 nl80211，
> 不加会报 `Driver does not support authentication/association or connect commands`。
> 另外 `iw dev wlan0 link` 对这个驱动永远显示 `Not connected`（iw 只认
> nl80211），查状态要用 `iwconfig`。

---

## 阶段 1：VM 起 broker（T2）

```sh
sudo service mosquitto start
sleep 2
sudo ss -tlnp | grep -E "1883|8083"
```

要看到 **1883 和 8083 都在 `0.0.0.0`** 上监听。1883 给板子，8083 给浏览器（WebSocket）。

没起来就看日志（不要用 `-c ~/edgemonitor/mosquitto.conf` 手动跑，那样开机不自启）：

```sh
sudo tail -15 /var/log/mosquitto/mosquitto.log
```

验证认证生效——不带密码应该被拒：

```sh
timeout 3 mosquitto_sub -h localhost -t 'test' -C 1
```

期望 `Connection Refused: not authorised`。

---

## 阶段 2：VM 交叉编译网关（T2）

先从本机传源码（**T1**）：

```powershell
scp -O -o HostKeyAlgorithms=+ssh-rsa "D:\UserFiles\Desktop\面试\远程监控系统_STM32_IMX6ULL\gateway_imx6ull\gateway_mqtt.c" user@192.168.100.6:~/edgemonitor/
```

VM 上编译（**T2**）：

```sh
cd ~/edgemonitor && arm-linux-gnueabihf-gcc -Wall gateway_mqtt.c -o gateway_mqtt -I mosquitto-1.6.15/lib mosquitto-1.6.15/lib/libmosquitto.a -lpthread -lm && file gateway_mqtt
```

`file` 输出里要有 `ARM`。如果报 `undefined reference to ares_*`，改动态链接（板子上有 `libmosquitto.so.1`）：

```sh
cd ~/edgemonitor && arm-linux-gnueabihf-gcc -Wall gateway_mqtt.c -o gateway_mqtt -I mosquitto-1.6.15/lib -L mosquitto-1.6.15/lib -lmosquitto && file gateway_mqtt
```

传到板子：

```sh
scp gateway_mqtt root@192.168.100.3:/home/root/
```

---

## 阶段 3：板子配置并启动（T3）

配置文件（密码换成自己设的）：

```sh
cat > /etc/edgemonitor.env <<'EOF'
MQTT_HOST=192.168.100.6
MQTT_USER=em
MQTT_PASS=你的密码
DEVICE_ID=robot01
EOF
chmod 600 /etc/edgemonitor.env
```

> **最容易错的一项**：`MQTT_HOST` 填 **VM 的地址**，不是 localhost。
> broker 已经搬到服务器侧了，填 localhost 会一直 `Connection refused`。

启动（`setsid` 让它脱离 SSH 会话，SSH 断了也不会跟着死）：

```sh
killall gateway_mqtt gateway_mqtt_static 2>/dev/null
cd /home/root && chmod +x gateway_mqtt
. /etc/edgemonitor.env && export MQTT_HOST MQTT_USER MQTT_PASS DEVICE_ID
setsid ./gateway_mqtt can0 >/tmp/gw.log 2>&1 </dev/null &
sleep 3 && cat /tmp/gw.log
```

期望输出：

```
CAN can0 ready
device=robot01 ip=192.168.100.3, online topic=monitor/online/robot01
[mqtt] connected, subscribed: monitor/cmd, online -> monitor/online/robot01
```

## 阶段 4：验证数据流（T4）

```sh
timeout 10 mosquitto_sub -h localhost -u em -P '你的密码' -t 'monitor/#' -v
```

应该刷出：

```
monitor/online/robot01 {"online":1,"dev":"robot01","ip":"192.168.100.3","video":8081}
monitor/data/status {"t":25.6,"h":62.3,"l":41,"d":78,"s":0}
monitor/data/imu {"p":1.2,"r":-0.5,"y":30.1}
monitor/data/motor {"rl":0,"rr":0,"ol":0,"or":0}
```

看到这些就说明 **STM32 → CAN → 板子 → MQTT → VM** 整条通了。

没有 `monitor/data/*` 只有 `online` → CAN 没数据，检查 STM32 是否在跑、
CAN 接线和 120Ω 终端电阻。

## 阶段 5：Web 大屏（T1 传，T2 起）

T1：

```powershell
scp -O -o HostKeyAlgorithms=+ssh-rsa "D:\UserFiles\Desktop\面试\远程监控系统_STM32_IMX6ULL\web\index.html" "D:\UserFiles\Desktop\面试\远程监控系统_STM32_IMX6ULL\web\app.js" user@192.168.100.6:~/edgemonitor/web/
```

T2：

```sh
mkdir -p ~/edgemonitor/web && cd ~/edgemonitor/web
setsid python3 -m http.server 8080 >/tmp/web.log 2>&1 &
sleep 1 && ss -tln | grep 8080
```

浏览器打开 **`http://192.168.100.6:8080`**，登录框填：

- Broker 地址：**`192.168.100.6`**（VM 自己，不是板子）
- 账号 `em` + 密码

登录后标题栏应该有两个独立状态：`已连接 192.168.100.6`（大屏↔broker）和
`robot01 在线`（设备本身）。视频会自动指向设备通告的 IP，不用手工配。

## 阶段 6：板子上的 Qt 界面（T3）

```sh
cd /home/root && setsid ./edgemonitor_ui -platform linuxfb >/tmp/ui.log 2>&1 </dev/null &
sleep 3 && ps | grep -v grep | grep edgemonitor_ui
```

> UI 的 broker 地址存在它自己的设置页里（QSettings），不读
> `/etc/edgemonitor.env`。第一次用要在界面上手动填 `192.168.100.6`。

## 阶段 7：进程守护（可选，但强烈建议）

不做的话，任意进程挂掉都要人工上去重启——现场吃过一次亏：WiFi 断开导致
SSH 会话终止，前台启动的 UI 收到 SIGHUP 退出，屏幕停在最后一帧看着像卡死，
其实进程早没了。

T1 传脚本：

```powershell
scp -O -o HostKeyAlgorithms=+ssh-rsa "D:\UserFiles\Desktop\面试\远程监控系统_STM32_IMX6ULL\deploy\sysvinit\edgemonitor-daemon.sh" root@192.168.100.3:/home/root/
```

T3 启动：

```sh
chmod +x /home/root/edgemonitor-daemon.sh
killall gateway_mqtt video_v4l2 edgemonitor_ui 2>/dev/null
setsid /home/root/edgemonitor-daemon.sh >/tmp/em_daemon.log 2>&1 &
sleep 12 && cat /tmp/em_daemon.log
```

验证自愈：

```sh
killall edgemonitor_ui && sleep 12 && ps | grep -v grep | grep edgemonitor_ui
```

10 秒内自己回来就对了。

开机自启还要编辑 `/etc/rc.local`，在 `exit 0` 前加：

```sh
setsid /home/root/edgemonitor-daemon.sh >/tmp/em_daemon.log 2>&1 &
```

同时把原有的 `/opt/QDesktop` 那行注释掉——它是出厂 Qt 桌面，会抢 framebuffer
和触摸屏。

## 阶段 8：OTA 升级（需要时）

固件在本机 Keil 编译，两份（A/B 双分区，链接地址不同不能互换）。

T1 传：

```powershell
scp -O -o HostKeyAlgorithms=+ssh-rsa "D:\UserFiles\Desktop\面试\远程监控系统_STM32_IMX6ULL\EdgeMonitor_App\Output\atk_f103_a.bin" "D:\UserFiles\Desktop\面试\远程监控系统_STM32_IMX6ULL\EdgeMonitor_App\Output\atk_f103_b.bin" root@192.168.100.3:/home/root/
```

T3 升级（传**基名**，不带 `_a.bin`，工具会问设备该写哪个槽）：

```sh
cd /home/root && ./uds_tool atk_f103 can0
```

串口能看到新固件试运行并自确认：

```
Trying pending slot B (attempt 1/3)
Jump to slot B @0x08040000
A/B: boot confirmed, active slot = B
```

## 编译 Qt 程序前必须 source SDK 环境

项目里有**两套互不相干的交叉工具链**：

| 程序 | 工具链 | 是否需要 source |
|------|--------|----------------|
| 网关几个 C 程序 | `arm-linux-gnueabihf-gcc` | 不用，在系统 PATH 里 |
| `edgemonitor_ui` (Qt) | `arm-poky-linux-gnueabi-g++` | **必须先 source** |

```sh
source /opt/fsl-imx-x11/4.1.15-2.1.0/environment-setup-cortexa7hf-neon-poky-linux-gnueabi
which arm-poky-linux-gnueabi-g++      # 有输出才算就位
```

`source` 只对当前终端有效，**每开一个新窗口都要重来一次**。

> 踩过的坑：忘了 source 时 `make` 不会明显失败——只要 `.o` 文件还在，
> 它就跳过编译直接链接旧对象文件，产出一个"看起来是新的、内容却是旧的"
> 二进制。部署上去之后现象是"改的代码完全没生效"，而时间戳、文件大小
> 全都显示已更新，极具迷惑性。
>
> **验证编译真的生效**，别只看 make 的退出码：
> ```sh
> strings edgemonitor_ui | grep -E "monitor/.*data"   # 应为 monitor/%1/data/#
> ```
> 另外别用 `make 2>&1 | tail -5` 这种写法看结果，错误信息会被截掉。

## 更新已在运行的程序（`Text file busy`）

守护脚本跑着的二进制不能直接 scp 覆盖，会报 `Text file busy`。
先传成临时名再 `mv` 替换——`mv` 换的是目录项，正在跑的旧进程继续用旧 inode，
不受影响，也不用先停守护脚本：

```sh
# VM 上
scp ~/edgemonitor/gateway_mqtt root@192.168.100.3:/home/root/gateway_mqtt.new
```

```sh
# 板子上：替换 + 杀掉旧进程，守护脚本 10 秒内拉起新版
mv -f /home/root/gateway_mqtt.new /home/root/gateway_mqtt
chmod +x /home/root/gateway_mqtt
killall gateway_mqtt
```

`edgemonitor_ui`、`video_v4l2` 同理。

## 常见问题速查

| 现象 | 原因 |
|------|------|
| `no matching host key type found` | SSH 缺 `-oHostKeyAlgorithms=+ssh-rsa` |
| 板子 `Connection refused` 连不上 broker | `MQTT_HOST` 还是 localhost，或 VM broker 没起 |
| `Driver does not support authentication` | wpa_supplicant 缺 `-D wext` |
| `iw dev wlan0 link` 显示 Not connected 但网络能用 | 正常，该驱动要用 `iwconfig` 看 |
| 界面"卡死"、数据不更新 | 进程可能已退出，`ps` 确认；多半是 SSH 断开导致的 SIGHUP |
| Web 登录后无数据 | 板子 gateway 没连上，看 `/tmp/gw.log` |
| OTA 报"设备不支持 A/B 查询" | 板子上的 Bootloader 是旧版，需要重新烧 Boot |
| scp 报 `Text file busy` | 目标程序正在运行，用上面的临时名 + `mv` 方式替换 |
| 界面/大屏收不到数据但 broker 正常 | 设备号不一致：网关用 `DEVICE_ID` 拼 topic，界面也要读同一个环境变量 |
