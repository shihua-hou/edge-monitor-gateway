# 开发环境搭建指南（i.MX6ULL ALPHA）

> 目标：把 PC + i.MX6ULL + STM32 三端环境一次配好，让"写代码→编译→部署→调试"闭环跑起来。
> 适用：Windows 主机 + i.MX6ULL ALPHA 板 + 战舰 STM32F103。

---

## 0. 环境全景（哪里装什么）

```
【PC 开发机 - Windows】               【板子 - i.MX6ULL ALPHA】      【板子 - 战舰STM32】
├ 写代码   VS Code                   ├ 系统 Ubuntu 镜像(推荐)       ├ Keil5 工程
├ STM32    Keil5                     ├ 跑: 网关程序/Qt/Web服务      ├ 烧录 ST-Link/串口
├ 连板子   MobaXterm(SSH+串口+传文件) ├ 服务: can0/mosquitto/Web     └ 调试 串口打印
├ 交叉编译 Ubuntu虚拟机/WSL/Linux    ├ 视频: MJPG-streamer
└ 资料包   正点原子ALPHA资料包(镜像/虚拟机/工具链/例程)
```

**一句话**：代码在 PC 写，STM32 用 Keil 编+烧，i.MX6ULL 程序在"交叉编译环境"编好后 scp 到板子跑。

---

## 1. 第一步：决定 i.MX6ULL 系统（影响一切）

ALPHA 板出厂是 **Buildroot 精简系统**（无 apt、可能无 gcc/python）。

| 方案 | 做法 | 适合 |
|------|------|------|
| **A 烧 Ubuntu（推荐）** | 资料包→系统镜像→MfgTool 烧 EMMC | 之后 apt 随便装，开发最顺 |
| B 保留 Buildroot | 全交叉编译，缺库就编库拷板 | 想保持原厂系统 |

**烧 Ubuntu（ALPHA）步骤**：
1. 资料包 `开发板系统镜像/` 找 i.MX6ULL Ubuntu 镜像（ALPHA 版）
2. 板子拨码开关设为 **USB 烧录模式**（参考资料包手册），USB OTG 线连 PC
3. PC 运行资料包工具 `MfgTool`，选对应配置 → 点 Start，一键烧写
4. 烧完拨回 **EMMC 启动**，上电
> 更简单备选：若资料包有 SD 卡 Ubuntu 镜像，用 win32diskimager 写 SD 卡启动即可。

## 2. PC 基础环境（Windows）

| 软件 | 用途 | 说明 |
|------|------|------|
| **MobaXterm** | SSH + 串口 + 文件拖拽 | 一站式，强烈推荐 |
| VS Code | 写代码 | 装 C/C++、Remote-SSH 插件 |
| Keil5 (MDK) | STM32 编译烧录 | 用正点原子战舰例程 |
| 正点原子资料包 | 镜像/虚拟机/工具链/例程 | ALPHA 完整资料 |

**安装要点**：
- MobaXterm 免费版够用：Session → SSH（填板子 IP）/ Serial（选 CH340 串口 115200）
- VS Code 装 **Remote-SSH** 插件后可远程编辑板子文件

## 3. 交叉编译环境（三选一，推荐 A）

i.MX6ULL 程序是 **ARM 架构**，PC 上要用交叉编译器编出 ARM 可执行文件。

### 方案 A：正点原子 Ubuntu 虚拟机（开箱即用，最省事）
资料包 → `开发板工具/Ubuntu虚拟机`（VMware 镜像，**已配好交叉编译器**）
```bash
# 打开虚拟机后验证
arm-linux-gnueabihf-gcc --version    # 有输出即 OK
```

### 方案 B：WSL（Windows 自带 Linux）
```powershell
wsl --install -d Ubuntu
```
然后在 WSL 里装交叉编译器（见下方通用命令）。

### 方案 C：双系统 Linux 笔记本（如果你有）
直接在 Linux 里装，性能最好。

### 通用：安装正点原子交叉编译器（A 之外用）
```bash
# 从资料包拷贝 gcc-linaro-xxx.tar.xz（ARM 交叉编译器）到 Linux
sudo mkdir -p /usr/local/arm
sudo tar -xf gcc-linaro-*.tar.xz -C /usr/local/arm
export PATH=/usr/local/arm/gcc-linaro-*/bin:$PATH   # 写入 ~/.bashrc
arm-linux-gnueabihf-gcc --version
```

**验证交叉编译（阶段 2 网关）**：
```bash
arm-linux-gnueabihf-gcc gateway_can.c -o gateway_can
file gateway_can    # 应显示 "ARM, 32-bit" 才算对
```

## 4. STM32 环境（战舰板）

**本项目现在是 Boot + App 两个独立 Keil 工程**（见 [docs/Bootloader_UDS设计.md](Bootloader_UDS设计.md)），先只建 App 工程把日常采集/控制跑起来，Boot 工程留到做 OTA 那一步再建。

> v2.1：正点原子现在的战舰V4资料包已经没有标准库(StdPeriph)例程了，只有
> 寄存器版本和 HAL 库版本，所以 App 侧改成基于 **官方 HAL 版 FreeRTOS 例程**
> 开发（`can.c`/`app_task.c`/`sensor/` 已经按 HAL 改好）。

1. 装 **Keil5 (MDK5)** + 正点原子战舰板资料包（`3，扩展例程/2，FreeRTOS例程`）
2. 安装 ST-Link/J-Link 驱动（或用串口 ISP）
3. 把本项目 `firmware_stm32/` 的 `can.c/can.h/app_task.c/app_task.h/
   bsp_delay.c/bsp_delay.h/types.h` 以及 `sensor/` 整个目录
   （`dht11.c/hcsr04.c/mpu6050.c/adc_light.c` 及对应 `.h`）加入 FreeRTOS
   例程工程——**传感器驱动都已经是真实实现，不是留空的 TODO**，直接编译
   链接即可；`main.c` 不要整体替换，按它文件头注释把三行调用插进官方例程
   自己的 main.c
4. 确认 `FreeRTOSConfig.h` 中 `configMAX_SYSCALL_INTERRUPT_PRIORITY = 5`
5. 编译 0 error → ST-Link/J-Link 下载 / BOOT0 拉高串口 ISP

## 5. 板子侧环境（i.MX6ULL ALPHA）

### 5.1 上电 + 登录
```bash
# 串口（CH340, 115200）或 SSH
MobaXterm → SSH → 192.168.1.232 (以 ifconfig 实际为准)
# 登录 root
```

### 5.2 配网（传文件 + Web 访问）
```bash
# 网线直连 PC 开发（推荐）
ifconfig          # 记下 eth0 IP，PC 配同网段
# 或 USB WiFi 连路由（远程用）
nmcli dev wifi connect "WiFi名" password "密码"    # Ubuntu 系统
```

### 5.3 确认 CAN（ALPHA 板载收发器）
```bash
ls /sys/class/net/          # 应看到 can0
ip link set can0 type can bitrate 500000
ip link set can0 up
ip -details link show can0  # 显示 bitrate 500000 即 OK
```

### 5.4 Ubuntu 系统下安装软件（阶段 5 之后需要）
```bash
apt update
apt install -y gcc make git libmosquitto-dev mosquitto mosquitto-clients python3 libjpeg-dev
```

## 6. 开发工作流（每阶段通用）

```
① PC 写代码
② 编译：STM32→Keil / i.MX6ULL→交叉编译
③ 部署：STM32→ST-Link烧录 / i.MX6ULL→scp
④ 调试：串口 / SSH / candump / mosquitto_sub
```

**scp 传文件（Windows 命令提示符 / PowerShell 或 MobaXterm）**：
```powershell
scp D:\...\gateway_can.c root@192.168.1.232:/root/monitor/
```
